# MVP 범위 확정 (Stage 1)

## 범위 원칙

사업계획서의 Phase 1(Core) + Phase 2(Format Engine) 전체 범위를 MVP 목표로 한다. 다만 개발인력이 대표자+풀스택 개발자 1명인 점을 고려해, "전체 범위"는 MVP 완성 시점의 기능 커버리지를 의미하고 실제 개발 착수 순서는 우선순위 그룹으로 나눠 진행한다(세부 티켓 분해는 07-개발마일스톤.md에서 다룬다).

## Phase 1: Core 상세 범위

1. **공연정보 입력**
   - 필수 4항목: 장르, 공연명, 날짜, 장소
   - 선택 항목: 부제, 공연시간, 러닝타임, 출연진, 티켓가격, 관람연령, 주최·주관, 후원, 문의, 예매처, 공연소개, 시놉시스, 프로그램, 공연사진, 출연진 사진, 로고, 참고 이미지, 색상, 필수 안내문구(포스터에 꼭 들어가야 하는 문구), 원하는 이미지 방향(자유서술)
   - 처음부터 전 항목을 강제하지 않고 필수 4개 → 이후 보강하는 흐름
   - 필수 4항목은 모두 채워야 다음 단계로 진행 가능(건너뛰기 없음). 다만 날짜·장소는 실제 값 대신 "미정"을 선택할 수 있다(장르·공연명은 미정 불가)
2. **공연정보 역할별 구조화** — 필드를 이미지 픽셀이 아닌 별도 데이터 객체로 관리 (상세는 Stage 2)
3. **장르별 배치 기준 적용** — 지원 장르 7종: 클래식, 무용, 연극, 뮤지컬, 어린이공연, 인디밴드, 대중음악
4. **기본 시안 생성 및 선택 UX** — 선택 / 다른 방향 보기 / 재생성 / 이 방향으로 더 보기
5. **프로젝트 생성** — 공연정보 + 디자인 자산 + 생성 결과를 하나의 프로젝트로 저장

## Phase 2: Format Engine 상세 범위

1. **지원 규격**
   - **원본 1종**: 포스터(세로 기본형) — ④ 시안 확정 시 생성되는 프로젝트당 1건의 대표 이미지이자 모든 변환의 기준. ⑤ 화면에는 "원본 다시 만들기"로 노출하되, 새 안을 확정하면 결과물이 추가되지 않고 기존 포스터가 교체된다(Stage 2·3 참고)
   - **변환 대상 12종**: NOL티켓·티켓링크·플레이티켓 대표이미지, SNS 1:1, SNS 4:5, SNS 스토리, 홈페이지 썸네일, 홈페이지 배너, DID, 공연장 모니터, 현수막, X배너
   - 주의: 현장 안내·포토존·MD 판매 이미지 등은 "같은 시안의 규격 변환"이 아니라 "새로운 목적의 디자인"이므로 Format Engine이 아닌 Phase 3(추가 제작물)로 분류
   - MVP는 위 기본 규격만 제공한다. 규격은 테이블이 아니라 코드 상수로 두며, 커스텀 규격이 열려도 결과물이 치수를 직접 들고 있으므로 스키마 변경이 없다(Stage 2·12 참고)
2. **복수 규격 선택 → 일괄 재구성** (Recomposition — 단순 리사이즈 아님: 제목 크기/위치, 이미지 크롭, 정보 삭제·축약, 로고 이동 등 규격별 재판단)
3. **규격별 복수안 제시**
4. **최소 객체 조정** — 제목/날짜/장소/출연진/사진/로고를 개별 객체로 유지, 위치 이동·크기 조정만 지원
5. **프로젝트 대시보드** — 결과 확인, 개별 선택, 선택 다운로드, 일괄 다운로드, 추가 제작 진입(진입 UI만, Phase 3 전까지 비활성), 인쇄 진입 → 인쇄 페이지(규격·수량·옵션·배송지 입력 + 예상금액 계산)까지는 MVP에서 실제로 제공. 단 결제·주문 접수 버튼은 비활성

## 기존 프로토타입 재사용 판단

보유 중인 프로토타입(BANDAL Performance Design, 공연정보 입력 → 배치안 비교 확인 흐름)은 단일 장르·단일 규격 수준의 검증이었다.

- **재사용**: UX 플로우 컨셉(선택 중심 UX), 프롬프트 설계 방향
- **신규 설계 필요**: 데이터 구조(Role Schema), 7개 장르 규칙, Format 규칙, 규격 엔진 — 프로토타입에는 없던 부분이므로 Stage 2·5에서 처음부터 설계

## 이번 MVP에서 제외 (이후 Phase로 이연)

- 추가 이미지 제작물(캐스트소개, 티켓오픈, 현장안내, 포토존, MD 등) → Phase 3
- 공연 상세페이지 → Phase 4
- 프로그램북·리플렛 → Phase 5
- 인쇄 실제 결제·주문 접수(PG 연동, 인쇄업체 발주 연동) → Phase 6. 단 인쇄 페이지 자체(규격·수량·용지·옵션·배송지 입력 + 예상금액 계산, PrintOrderDraft)는 MVP 범위에 포함하며 주문 버튼만 비활성 상태로 제공(인쇄 전제 조건인 재단여백·해상도 기준은 Format Rules 설계 시 함께 반영)
- 크레딧 **결제(충전)** → Phase 6. 단 **크레딧 차감 로직 자체는 MVP에 포함**한다. 나중에 붙이면 소비량 데이터가 없어 단가를 정할 근거가 생기지 않는다(Stage 6)
- Enterprise·기관 다중사용자 → Phase 6
- 커스텀 규격 입력(사용자가 가로×세로 직접 지정) → 최종 서비스 목표 기능. MVP는 사전 정의 프리셋만 제공하고, 커스텀 입력 지원 시점은 이후 Phase에서 별도 판단

## 사업계획서 전체에서 제외된 항목 (재확인)

공연 정산, 인력관리, 대관관리, 공연장 ERP, 티켓 판매, 좌석·발권 관리, 커뮤니티, 광고집행, 범용 PPT 제작, 범용 디자인 에디터

## MVP 성공 기준

- **제품 지표**: 정보입력 → 시안생성 → 선택 완료율, 규격 일괄변환 결과 다운로드율
- **검증 목표**: 목표 고객 인터뷰(20건) 중 정보입력 → 일괄변환 → 다운로드까지 완주하는 사용자 비율 확인
- **운영 조건**: 베타는 결제 없이 관리자 지급 크레딧으로 운영한다. 프로젝트 개수는 제한하지 않으며, 사용량은 크레딧으로만 통제한다(Stage 6)

## 개발 착수 우선순위 (전체 범위를 순차적으로 구현)

1. 정보입력 + Role Schema + 단일 장르 기본 시안 생성 (전체 구조의 뼈대)
2. 장르 규칙 확장 (7개 장르 순차 적용)
3. 규격 엔진 기본형 (핵심 규격 4~5종부터)
4. 규격 목록 전체 확장
5. 프로젝트 대시보드 고도화

그랜트 심사 피드백("개발인력 규모 대비 구현 가능성 우려")을 반영해, 전체 마일스톤 중 어디까지가 협약기간 내 목표인지는 Stage 7(개발마일스톤)에서 구간으로 별도 표시한다.
