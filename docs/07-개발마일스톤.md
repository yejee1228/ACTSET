# 개발 마일스톤 (Stage 7)

## 목적

Stage 0~6 문서를 실제 개발 착수 단위(에픽 → 티켓)로 쪼개고, 우선순위와 협약기간(그랜트 라운드) 내 목표 구간을 표시한다. 이 문서는 기능 구현 순서를 정하며, 실제 작업 티켓은 Stage 13에서 분해한다.

## 개발 착수 전 선행 작업 (에픽 0)

- 이미지생성 API·VLM·LLM 벤더 확정(Stage 5 확인사항, Stage 6 확인사항과 연결) — 이후 모든 에픽의 실제 구현 난이도에 영향을 준다
- Genre Rules 부트스트랩 리서치 착수(실제 포스터 다수 분석) — 개발과 병행 가능하나 ③ 시안 생성 품질에 필요
- 인쇄 협력업체 협의(PrintOrderDraft 단가표, Stage 2·6)
- **PoC 2차 검증**(Stage 8의 Q1·Q2·Q4·Q6·Q7) — 레이어 분해 품질과 아웃페인팅이 규격 변환 전략을 좌우하므로 개발 착수 전에 확인한다

## 에픽 구성 (Stage 1 우선순위 그룹을 티켓 단위로 확장)

### 에픽 1 — 뼈대: 진입 구조 + 정보입력 + Role Schema + 단일 장르 기본 시안 생성

- 계정·인증(회원가입/로그인)
- 0-A 소개 페이지(비로그인 첫 화면), 0-B 홈 대시보드(로그인 후 첫 화면, 프로젝트 목록 + "새 프로젝트 만들기")
- Project(draft/active) / PerformanceInfo / GeneratedAsset / SelectionEvent / CreditTransaction 스키마 구현(Stage 10). 규격은 코드 상수
- ① 공연정보 입력 화면(진입 시 draft 프로젝트 생성, 자동저장, 미정 처리 포함)
- ② 추가정보 입력 화면(9개 그룹 — 문구·이미지 방향 포함)
- ③ 시안 선택 화면 + SelectionEvent 로깅
- ④ 시안 확정 + ④-1 다음 행동 선택
- 이미지 생성 API 연동(장르 1개만 우선 — 예: 정보 구조가 단순한 장르부터)
- **협약기간 내 목표**: 이 에픽까지 완료되면 "공연정보 입력 → 시안 생성 → 선택 → 프로젝트 생성"이 데모 가능해진다

### 에픽 2 — 장르 규칙 확장

- Genre Rules 데이터 구조 구현(Stage 5)
- 7개 장르 순차 적용(부트스트랩 리서치 결과 반영)

### 에픽 3 — 규격 엔진 기본형

- FormatRule 데이터 구조 구현
- Recomposition Engine 기본 로직(핵심 규격 4~5종: SNS 1:1·SNS 4:5·스토리·현수막 등. 포스터는 원본이라 변환 대상이 아니며 재생성은 별도 경로)
- 비고: 에픽 4의 "나머지 규격"에서 스토리는 제외된다(여기서 이미 구현)
- ⑤ 규격 선택 화면, ⑥ 일괄변환 화면(최소 편집 모드 포함)

### 에픽 4 — 규격 목록 전체 확장

- 나머지 규격 추가(예매처 이미지 3종·홈페이지 썸네일/배너·DID·공연장 모니터·X배너)

### 에픽 5 — 프로젝트 대시보드 고도화

- ⑦ 프로젝트 대시보드(대표 포스터 영역, 다운로드, 개별 삭제, 최신 반영, 미정 경고 배지, 다운로드 만료 표시)
- 포스터 원본 재생성 경로(⑤ "원본 다시 만들기" → 기존 포스터 교체 + DesignAssets 갱신 + "원본 변경됨" 배지)
- 6-1 정보 수정 화면 + 포스터 자동반영/그 외 수동반영 로직
- 정리 배치 작업 일체(Stage 10의 정리 배치 표 참조 — 소프트 삭제 결과물·미확정 draft·삭제 프로젝트·탈퇴 계정·미선택 시안후보·만료 대용량 파일·죽은 작업)
- 프로젝트 복제 기능(홈 대시보드 카드 메뉴)
- 비고: 홈 대시보드 화면 자체는 에픽 1에서 이미 구현하고, 여기서는 복제·필터 등 부가 기능만 얹는다

### 에픽 6 — 인쇄 페이지 (MVP 범위)

- ⑧ 인쇄 페이지(입력 폼 + 예상금액, 주문 버튼 비활성)
- PrintOrderDraft, 플레이스홀더 단가표

### 에픽 7 — 베타 운영 준비

- 크레딧 차감·환불 로직과 잔액 화면(Stage 6)
- 고객 인터뷰(목표 20건)용 피드백 수집 채널

## 우선순위 및 협약기간 내 목표 표시

| 에픽 | 우선순위 | 협약기간 내 목표 |
|---|---|---|
| 0. 선행 작업(벤더 확정 등) | 최우선 | 포함 |
| 1. 뼈대 | 1 | 포함 — 데모의 핵심 |
| 2. 장르 규칙 확장 | 2 | 최소 2~3개 장르까지 포함, 나머지는 이후 라운드 |
| 3. 규격 엔진 기본형 | 3 | 포함(핵심 규격 4~5종) |
| 4. 규격 목록 전체 확장 | 4 | 이후 라운드 |
| 5. 대시보드 고도화 | 5 | 다운로드·삭제 등 최소 기능만 포함, 나머지는 이후 |
| 6. 인쇄 페이지 | 6 | 이후 라운드 |
| 7. 베타 운영 준비 | 에픽1과 병행 | 포함 — 고객 인터뷰 20건 목표와 직결 |

이 표는 그랜트 심사에서 받은 "개발 규모 대비 구현 가능성 우려" 피드백에 대응하기 위해, 전체 마일스톤 중 협약기간에 해당하는 구간만 별도로 표시한 것이다(Stage 1에서 예고한 방식).

## 확인이 필요한 사항

1. 실제 협약기간(라운드 일정, 개월 수)이 확정되면 위 우선순위 표를 구체적 주 단위 일정으로 재작성해야 한다
2. Genre Rules 부트스트랩 리서치를 개발과 병행할지, 에픽 1 착수 전에 선행할지 결정 필요

## Stage 13 에픽과의 대응 (중요)

Stage 13에서 티켓으로 분해하며 **에픽 묶음이 재편되었다.** 번호가 같아도 내용이 다르므로 아래 표를 기준으로 읽는다. 실제 개발 진행은 **Stage 13의 에픽 구분을 따른다.**

| Stage 7 에픽 | Stage 13 에픽 | 비고 |
|---|---|---|
| 0. 선행 작업 | **E0** | Stage 15의 법무·메일 항목(0-5~0-9)이 추가됨 |
| 1. 뼈대 | **E1** + E1 필수 부속 + E1-P | Stage 15에서 식별한 필수 항목이 대거 추가됨 |
| 2. 장르 규칙 확장 | **E2 학습 파이프라인** | "규칙을 손으로 정한다"에서 "포스터를 학습해 산출한다"로 성격이 바뀌었다(Stage 5) |
| 3. 규격 엔진 기본형 + 4. 규격 전체 확장 | **E3 규격 엔진** | 규격이 상수로 정의되어 4가 별도 에픽일 이유가 없어졌다(Stage 12) |
| 5. 대시보드 고도화 | **E4 대시보드·정보 반영** | |
| 6. 인쇄 페이지 | **E5 인쇄 페이지** | |
| 7. 베타 운영 준비 | **E6 베타 운영 준비** | 퍼널·소비 분포 집계가 추가됨 |

## 기획 단계 마무리

00~07은 **서비스 기획**이며, 이어지는 08~15가 **개발 기획**이다(Stage 0의 로드맵 참고). 개발 중 새로 발견되는 이슈는 해당하는 단계 문서로 돌아가 갱신한다.
