# 플랫폼 사업모델 — CREATE + DISCOVER 순환 구조 (Stage 17)

> **개정 이력**: 2026년 9월, ACTSET의 사업모델이 "AI 홍보물 제작 SaaS"에서 "제작을 통해 공연정보를 축적하고, 축적된 정보를 구독형 탐색 플랫폼으로 전환하며, 탐색이 다시 제작으로 이어지는 순환형 플랫폼"으로 개편되었다. **ACTSET을 단순 제작 SaaS로 해석하지 않는다.** 과거 문서(00~16)의 서술과 이 문서가 충돌하면 **이 문서를 우선**한다. 다만 이미 확정된 MVP 범위·Role Schema·레이어 구조·기술스택·개발 마일스톤은 유지하며, 이 문서는 그 위에 사업모델 층위를 추가하는 것이지 갈아엎는 것이 아니다.

## 목적

Stage 0~16이 정의한 것은 "홍보물 제작 도구"의 기능 명세다. 이 문서는 그 제작 기능이 **왜 존재하고 무엇으로 이어지는지**, 즉 ACTSET이라는 사업이 실제로 무엇으로 돈을 벌고 무엇으로 장기 해자를 쌓는지를 정의한다. 01(MVP 범위)이 "무엇을 만드는가"라면, 이 문서는 "그것이 사업적으로 왜 필요한가"다.

## 1. 순환 구조 (플라이휠)

```
홍보물 제작(CREATE) → 공연정보·디자인·선택 데이터 축적
      ↑                              ↓
새 프로젝트 생성 ← "참고해서 내 포스터 만들기" ← 콘텐츠화(Gallery 등록)
      ↑                              ↓
   플랫폼 데이터 증가          탐색(DISCOVER) — 구독 기반 열람
      ↑                              ↓
                          공연·디자인 Reference 발견
                                     ↓
                          (다시 맨 위 "참고해서 만들기"로)
```

제작은 더 이상 최종 산출물이 아니라 **고객획득 수단이자 공연정보 수집 수단**이다. 축적된 공연정보는 구독형 탐색 플랫폼(Gallery)의 콘텐츠가 되고, 탐색 중 발견한 공연·디자인이 다시 새로운 제작으로 연결되어 순환이 이어진다. 이 순환이 반복될수록 플랫폼의 데이터량이 늘어나고, 데이터량이 늘수록 탐색의 가치와 제작 추천의 정확도가 함께 오른다 — 이것이 사업계획서가 말하는 "데이터가 만드는 장기 진입장벽"의 실체다(기존 Stage 5 SelectionEvent 설계와 같은 맥락이며, 대상이 선택 데이터에서 공연·디자인 데이터 전체로 확장된 것이다).

## 2. 두 핵심 제품

| 제품 | 정의 | 기존 문서와의 관계 |
|---|---|---|
| **CREATE** | 공연정보 입력 → AI 포스터 생성 → 규격 변환 → 프로젝트 관리까지, 지금까지 00~16이 기술한 제작 기능 전체 | 그대로 유지. 이 문서가 새로 정의하지 않는다 |
| **DISCOVER** | 축적된 공연·디자인 정보를 구독 기반으로 탐색하는 Gallery. 공연 탐색과 디자인 탐색을 함께 제공 | **신규**. 00~16에는 존재하지 않던 개념이며, 최소 형태(비공개 기본 + 최소 목록/상세)만 MVP에 포함된다(Stage 1 참고) |

CREATE 단독으로는 반복 매출이 공연 주기에 묶여 있어 성장 한계가 뚜렷하다(Stage 6 "공연자는 매달 공연을 만들지 않는다" 참고). DISCOVER는 공연을 만들지 않는 달에도 탐색·구독으로 매출이 발생하게 하고, 동시에 CREATE의 재유입 경로(참고해서 만들기)를 제공한다.

## 3. 세 가지 데이터 자산 — 기존 엔티티와의 매핑

사업계획서는 플랫폼이 쌓는 데이터를 세 갈래로 정의한다. 이는 새 엔티티가 아니라 **Stage 2가 이미 정의한 엔티티를 자산 관점에서 재분류한 것**이다.

| 데이터 자산 | 정의 | 대응하는 기존 엔티티(Stage 2) |
|---|---|---|
| Performance Data | 공연명·장르·일정·장소·가격·출연진·작품정보 | `PerformanceInfo` |
| Creative Data | 레이아웃·디자인·색감·음악·영상·공연 해석 | `DesignAssets`(visual_layers·palette 등), `LayoutSample` |
| User Preference Data | 선택·거절·후보·재생성·다운로드 행동 | `SelectionEvent`, 그리고 신규 후보함(아래 7) |

세 자산 모두 이미 MVP 스키마에 존재하거나(Performance Data, User Preference Data) 최소한의 확장만으로 포괄된다(Creative Data — 음악·영상 해석은 Beta 확장 필드로 후속 추가, 아래 4·10 참고). **새 사업모델이 요구하는 것은 새 데이터 구조가 아니라 기존 데이터를 Gallery로 내보내는 경로**다(Stage 2·10에 반영).

## 4. Gallery 부트스트래핑 전략 — KOPIS

Gallery는 자체 프로젝트만으로는 초기 콘텐츠가 부족하다(사업 초기에는 CREATE 이용자 수 자체가 적다). 이를 보완하기 위해 **공공데이터포털의 공연정보(KOPIS, 국고 공연예술통합전산망)**를 초기 시드 데이터로 활용한다.

| 단계 | 데이터 구성 |
|---|---|
| 초기 | KOPIS 공연정보 위주 |
| 성장기 | KOPIS + 자체 프로젝트 혼합 |
| 장기 | 자체 프로젝트 비중 점진적 증가 |

KOPIS 데이터는 Performance Data(공연명·일정·장소 등)만 제공하며 Creative Data(디자인·레이아웃)는 포함하지 않는다는 점에 유의한다 — 즉 KOPIS로 채워지는 것은 "공연 탐색"이고, "디자인 탐색"은 자체 프로젝트가 쌓여야 채워진다. KOPIS 연동은 **MVP 범위가 아니라 MVP 이후 최우선 후속 작업**으로 이연한다(Stage 1·13). 라이선스·이용약관 확인은 E0에서 선행한다(Stage 14 참고).

## 5. 프로젝트 공개 정책 (확인필요 — 원칙만 확정)

| 상태 | 처리 |
|---|---|
| 제작 중 | **비공개(기본값)** |
| 공개 예정일 도달 또는 사용자 승인 | Gallery에 공개 |
| 향후(Beta 이후) | 유료 비공개 유지권 검토 |

정확한 전환 트리거(예정일 자동 공개 vs 수동 승인만)와 유료 비공개권의 가격·조건은 **원천 사업계획서에 확정값이 없으므로 확인필요**로 둔다. MVP는 "비공개 기본 + 사용자가 명시적으로 공개 전환" 하나만 구현하고(Stage 2·10), 예정일 자동 공개와 유료 비공개권은 후속 Phase로 이연한다.

## 6. "참고해서 내 포스터 만들기" (Reference-based Creation)

Gallery에서 발견한 공연·디자인을 자신의 새 프로젝트 제작에 참고하는 기능. **복제(클론)가 아니다.**

- 추출 대상: 색조, 정보밀도, 레이아웃 성향, 이미지·텍스트 비중, 여백, 시각적 분위기 — 즉 `LayoutSample`이 이미 학습 파이프라인용으로 추출하는 것과 같은 종류의 **스타일 속성**(Stage 5 0-3 참고)
- 추출하지 않는 것: 참고 대상의 공연정보(공연명·일정·장소·출연진 등)나 픽셀 자체
- 결과: 참고한 사용자 자신의 PerformanceInfo로 새 프로젝트를 시작하되, 추출된 스타일 속성이 시안 생성의 방향성 힌트로 반영됨

기술적으로는 학습 파이프라인이 이미 구현하는 레이아웃 분석 로직을 재사용하는 것이며, 별도 PoC가 필요하지 않다(Stage 5·8 참고).

## 7. 후보함 (Candidate Favorites) — 신규 MVP 기능

③ 시안 선택 화면(및 ⑥ 일괄변환 화면)에서 나온 시안 후보 중 최대 **5개까지 무료로 즐겨찾기**할 수 있는 기능. 재생성(유료)과 구분되는 **무과금 액션**이다(Stage 6 무과금 항목 목록에 추가).

- 즐겨찾기는 나중에 다시 훑어보고 선택하기 위한 것이며, 그 자체로 크레딧을 소비하지 않는다
- 5개를 초과해 담으려 하면 기존 항목을 해제해야 추가할 수 있다(서버에서 개수 제한을 강제 — Stage 2·10·11)

## 8. 수익원 — 다섯 축

기존 사업계획서의 수익 구조 네 축(크레딧·구독·인쇄·B2B, Stage 6 "사업계획서와의 차이" 참고)에 **Campus를 추가해 다섯 축**으로 재정의한다.

| 수익원 | 내용 | MVP 포함 여부 |
|---|---|---|
| Credit | 시안 생성·재생성 등 생성 행위 과금(Stage 6) | MVP 포함(결제는 Phase 6, 차감 로직은 MVP) |
| Subscription | DISCOVER 구독 — 제작혜택(약 2배 크레딧) + 정보혜택(Gallery 상세 열람) | **Beta 이후**. 가격 미확정(Stage 6 참고) |
| Print | 인쇄 연계 | Phase 6(Stage 1 기존 방침 유지) |
| Enterprise | 기관·단체 다중 사용자 계약 | Phase 6(Stage 1 기존 방침 유지) |
| **Campus** (신규) | 대학·학과 단위 대량 계정 — B2B 매출인 동시에 향후 개별 예술가 사용자 확보를 위한 유입 채널 | Beta 이후. MVP 범위 아님 |

## 9. KPI 프레임워크 — 여섯 카테고리

기존 MVP 성공 기준(Stage 1의 완주율·다운로드율)을 포괄하면서 플랫폼 단계의 지표를 추가한다. **아래 카테고리 구조만 확정이며, 개별 목표 수치는 확인필요**다.

| 카테고리 | 대표 지표(예시) |
|---|---|
| 제작 KPI | 정보입력→시안생성→선택 완료율, 규격 변환 다운로드율(Stage 1 기존 지표 유지) |
| Monetization KPI | 크레딧 재충전율(Stage 6에서 이미 재정의됨), 구독 전환율(Beta 이후) |
| Retention KPI | 두 번째 프로젝트 생성률, 재방문 주기 |
| Platform KPI | Gallery 등록 공연 수, DAU/MAU(탐색) |
| Conversion KPI | Gallery 열람 → "참고해서 만들기" 전환율 → 신규 프로젝트 생성률 |
| Data KPI | 축적된 LayoutSample·SelectionEvent 규모, 장르별 표본 충분도(Stage 5 0-3의 성숙 단계와 연결) |

## 10. 포스터 품질 전략 재정의

기존 문서는 명시하지 않았던 품질 목표를 명확히 한다: **전문 디자이너 수준의 품질을 목표로 하지 않는다.** 목표는 "가격 대비 충분한 품질"이며, 이와 동등하거나 더 큰 비중을 두는 것은 다음이다.

- 생성 속도
- 규격 정확성(Stage 12 비율 구간 구조)
- 정보 정확성(Stage 2 Role Schema·오타 없는 텍스트 레이어링, Stage 5)
- 프로젝트 관리 편의성(Stage 2·4의 대시보드·최신반영)
- 플랫폼 가치(DISCOVER 접근성)

**음악·영상 분석**은 이 맥락에서 "품질을 최대화하는 기능"이 아니라 "공연별 맥락을 반영해 생성 이미지가 일반 AI 이미지처럼 획일화되는 것을 줄이는 보조 기능"으로 재정의한다. 그리고 이 기능은 **Beta 전용이며 현재 MVP 범위에 포함되지 않는다** — MVP의 핵심은 어디까지나 포스터 생성, 후보 선택, 규격 Recomposition, 프로젝트 관리, 크레딧, 최소 Gallery다(Stage 1 참고).

## 11. 사업 단계 진화

```
Tool → SaaS → Content Platform → Performing Arts Infrastructure
```

- **Tool**: 프로토타입 단계(BANDAL Performance Design)
- **SaaS**: CREATE 단독, MVP~Beta 초기(현재 00~16이 정의한 범위)
- **Content Platform**: DISCOVER 추가, Gallery가 콘텐츠로서 독립적 가치를 갖는 단계
- **Performing Arts Infrastructure**: 공연 업계 전반의 정보·창작 인프라로 확장되는 장기 목표

MVP·Beta는 여전히 "SaaS" 단계에 속하며, 이 문서가 정의하는 DISCOVER는 "Content Platform" 단계로 넘어가기 위한 최소 다리(최소 Gallery)를 지금 놓는 것이다.

## 12. 최종 서비스 정의

> ACTSET은 공연 홍보물을 AI로 제작하는 도구(CREATE)이자, 그 과정에서 축적되는 공연·디자인 정보를 구독 기반으로 탐색하는 플랫폼(DISCOVER)이다. 제작이 데이터를 만들고, 데이터가 탐색 가치를 만들고, 탐색이 다시 제작으로 이어지는 순환 구조로 성장한다.

이 정의는 01(MVP 범위)의 "최종 서비스 정의" 절에서 재인용되며, 01의 "MVP 범위" 절은 이 최종 정의 중 지금 구현하는 부분만을 좁혀서 규정한다.

## 13. MVP와의 경계 — 요약

이 문서가 서술하는 것 중 **MVP에 포함되는 것은 최소 Gallery(비공개 기본, 최소 목록/상세)와 후보함(최대 5, 무료)뿐**이다. 아래는 모두 MVP 범위 밖이며 Beta 이후 또는 후속 Phase로 이연한다(상세는 Stage 1 참고).

- 음악·영상 분석(Beta 기능)
- 구독(Subscription)
- KOPIS 연동(부트스트래핑)
- Enterprise·Campus 계약
- 실제 인쇄 결제 연동(기존 Stage 1 Phase 6 방침과 동일)
- 참고해서 만들기의 전면 노출(최소 Gallery에 상세 진입 정도만 우선 포함, 전면적인 발견→참고 UX 고도화는 후속)

## 확인이 필요한 사항

1. 프로젝트 공개 전환의 정확한 트리거(예정일 자동 vs 수동 승인) — 원 사업계획서에 확정값 없음
2. 유료 비공개 유지권의 가격·조건 — Beta 이후 결정 사항으로 명시됨
3. 구독 가격 — "제작혜택 약 2배 크레딧 + 정보혜택"이라는 원칙만 있고 금액 미정(Stage 6 참고)
4. KOPIS API 이용약관·라이선스·데이터 갱신 주기 — E0에서 확인(Stage 14)
5. KPI 각 카테고리의 목표 수치 — 카테고리 구조만 확정, 수치는 데이터 축적 후 결정
