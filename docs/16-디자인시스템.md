# 디자인 시스템 (Stage 16)

> **서비스 UI의 디자인 명세다.** 홍보물(포스터·규격변환 결과물)의 디자인 규칙은 GenreRule·FormatRule·장르별 DESIGN.md(Stage 5)가 담당하며 이 문서와 무관하다. 이 구분에서 나오는 제1규칙: **결과물에는 ACTSET 브랜드 색을 절대 넣지 않는다.** 워터마크·프레임·오버레이 어떤 형태로도.

## 브랜드

| 항목 | 내용 |
|---|---|
| Personality | **Energetic · Creative · Precise · Professional** |
| 원칙 1 | "콘텐츠가 주인공이고, ACTSET은 그것을 가장 잘 보여주는 무대가 된다." |
| 원칙 2 | "포스터부터 인쇄까지, 공연 홍보를 위한 한 세트" |

네 가지 개성이 UI에서 갈라지는 지점을 명확히 해둔다. **Energetic·Creative는 오렌지와 콘텐츠(공연 포스터)가 담당**하고, **Precise·Professional은 그 밖의 모든 것** — 중립 색, 정렬, 간격, 숫자 표기 — 이 담당한다. 오렌지로 활기를 내고 나머지로 신뢰를 만든다. 이 역할 분담이 무너지면(온갖 곳이 오렌지가 되면) 창작도구도 업무도구도 아니게 된다.

### UI 톤

- 따뜻한 뉴트럴 바탕 — 순백·순회색이 아니라 웜 그레이 계열
- 오렌지는 **핵심 액션 컬러** — 행동을 부르는 곳에만
- 공연 포스터가 가장 먼저 보이는 구조
- 명확한 위계와 넉넉한 여백
- 창작도구답지만 업무도구처럼 신뢰감 있는 인상

## 1. 컬러

### 1-1. 기본 팔레트 (확정 8색)

| 토큰 | 값 | 용도 |
|---|---|---|
| `--orange` (Primary Orange) | `#FF6A2A` | 주요 CTA 배경, 진행 표시, 선택 링 |
| `--orange-deep` (Deep Orange) | `#E95516` | CTA hover, 강조 아이콘 |
| `--orange-soft` (Soft Orange) | `#FFF0E8` | 선택 배경, 배지 배경, hover 배경 |
| `--charcoal` (Charcoal) | `#1F1F1F` | 기본 텍스트, 강한 위계 |
| `--gray-warm` (Warm Gray) | `#6B6865` | 보조 텍스트, 비활성 라벨 |
| `--border` (Border) | `#E7E3DF` | 구분선, 카드·입력 테두리 |
| `--bg` (Background) | `#FAF8F5` | 앱 바탕 |
| `--surface` (White) | `#FFFFFF` | 카드·모달·입력 표면 |

### 1-2. 파생 토큰 (기본 8색에서 유도)

| 토큰 | 값 | 유도 근거 |
|---|---|---|
| `--orange-pressed` | `#CC4A12` | Deep Orange보다 한 단계 어둡게 — pressed 상태 |
| `--orange-text` | `#BC3E0C` | **흰 바탕 위 오렌지 텍스트·링크 전용.** Primary Orange는 텍스트로 쓰기에 너무 밝다(아래 대비 검증) |
| `--gray-disabled` | `#A8A49F` | Warm Gray를 연하게 — 비활성 텍스트·아이콘 |
| `--bg-hover` | `#F3F0EC` | Background를 한 단계 눌러 — 리스트 행 hover |
| `--focus-ring` | `#E95516` (2px, offset 2px) | 키보드 포커스. 오렌지 계열로 통일 |

### 1-3. 시맨틱 컬러

이 서비스는 상태 표시가 많다(정보 변경됨·원본 변경됨·미정·실패·만료). 오렌지가 액션 컬러이므로 **시맨틱 색은 오렌지와 혼동되지 않게** 고른다.

| 토큰 | 값 | 배경쌍 | 용도 |
|---|---|---|---|
| `--success` | `#1B7F4B` | `#E8F5EE` | 작업 완료, 저장됨 |
| `--warning` | `#7A5B00` | `#FFF6DE` | 해상도 부족, 일정 미정 경고 — **앰버 계열. 오렌지를 경고에 쓰지 않는다** |
| `--error` | `#C93030` | `#FCEBEB` | 생성 실패, 검증 오류 — 순수 레드. 오렌지와 확실히 구분 |
| `--info` = `--orange-text` | `#BC3E0C` | `#FFF0E8` | "정보 변경됨"·"원본 변경됨"처럼 **사용자 행동을 부르는 알림** — 액션을 유도하므로 오렌지 계열이 맞다 |
| `--neutral-badge` | `#6B6865` | `#F3F0EC` | 미정, 보관, 다운로드 만료 — 행동을 부르지 않는 상태 |

### 1-4. 대비 검증 (WCAG AA 기준, 실측)

| 조합 | 대비 | 판정 |
|---|---|---|
| Charcoal `#1F1F1F` / Background `#FAF8F5` | 15.6:1 | ✅ 본문 |
| Warm Gray `#6B6865` / Background | 5.2:1 | ✅ 보조 텍스트 |
| White / Primary Orange `#FF6A2A` | **2.9:1** | ⚠️ 일반 텍스트 기준(4.5:1) 미달 |
| White / Deep Orange `#E95516` | 3.6:1 | ⚠️ 미달 (대형 텍스트 3:1은 통과) |
| White / `--orange-pressed` `#CC4A12` | 4.6:1 | ✅ |
| `--orange-text` `#BC3E0C` / White | 5.5:1 | ✅ 일반 텍스트 |
| `--orange-text` / Soft Orange `#FFF0E8` | 4.9:1 | ✅ 배지 조합 |
| `--error` `#C93030` / White · `#FCEBEB` | 5.3 · 4.6:1 | ✅ |
| `--success` `#1B7F4B` / White · `#E8F5EE` | 5.0 · 4.5:1 | ✅ |
| `--warning` `#7A5B00` / White · `#FFF6DE` | 6.3 · 5.9:1 | ✅ |

여기서 나오는 **강제 규칙 두 가지**:

1. **오렌지 배경 버튼의 텍스트는 16px semibold 이상**으로 쓴다. 흰 글자 + Primary Orange 조합은 작은 텍스트에서 AA에 미달하므로, 주요 CTA는 크게(권장 크기 참조), 작은 버튼은 오렌지 배경 대신 아웃라인·텍스트 버튼으로 만든다.
2. **흰 바탕 위 오렌지 글자는 반드시 `--orange-text`(#BC3E0C)**를 쓴다. `#FF6A2A`를 텍스트 색으로 쓰지 않는다.

### 1-5. 오렌지 사용 규칙 — 이 문서에서 가장 중요한 절

"콘텐츠가 주인공"이라는 원칙은 색 규칙으로 번역된다. **오렌지는 넓게 칠하는 색이 아니라 찍는 색이다.**

1. **화면당 filled 오렌지 CTA는 1개가 원칙이다.** 그 화면에서 사용자가 다음으로 해야 할 행동 하나에만 준다. (예: ①에서는 "다음", ③에서는 "이 시안으로 확정", ⑦에서는 "일괄변환 만들기")
2. **결과물 이미지와 맞닿는 곳에 채도색을 두지 않는다.** 시안 카드·포스터 영역·미리보기 그리드 주변 UI는 무채색·뉴트럴로만 구성한다. 예외는 **선택 상태 표시 하나** — 선택된 시안·규격 카드의 2px 오렌지 링.
3. **오렌지가 허용되는 자리**: 주요 CTA, 진행 표시(프로그레스 바·스피너), 선택 링·체크, 포커스 링, 행동을 부르는 배지(`--info`), 크레딧 잔액 강조.
4. **오렌지가 금지되는 자리**: 본문 텍스트, 아이콘 기본색, 헤더·네비 배경, 대면적 배경(Soft Orange만 대면적 허용), 경고·오류(각각 앰버·레드가 담당), 그리고 **홍보물 결과물 그 자체**.
5. 오렌지 총량 감각치: 한 화면에서 채도 오렌지(`#FF6A2A`·`#E95516`)가 차지하는 면적은 **5% 이하**여야 한다. 그 이상이면 어떤 요소가 CTA인지 알 수 없게 된다.

## 2. 타이포그래피

**서체: Pretendard** (SIL OFL — Stage 9의 폰트 방향과 일치). 폴백 스택:

```
Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI",
"Malgun Gothic", "Apple SD Gothic Neo", sans-serif
```

이 서체는 **서비스 UI 전용**이다. 홍보물 렌더링(TITLE·INFO 레이어)의 서체는 장르·시안별로 엔진이 정하며 이 스택과 무관하다.

| 토큰 | 크기/행간 | 굵기 | 용도 |
|---|---|---|---|
| `display` | 28/38 | 700 | 0-A 소개 페이지 헤드라인 전용 |
| `h1` | 24/32 | 600 | 화면 제목 (화면당 1개) |
| `h2` | 20/28 | 600 | 섹션 제목 |
| `h3` | 16/24 | 600 | 카드 제목, ② 아코디언 그룹 헤더 |
| `body` | 15/23 | 400 | 기본 본문·입력값 |
| `body-strong` | 15/23 | 600 | 강조 본문, 버튼 레이블 |
| `body-sm` | 13/20 | 400 | 보조 설명, 카드 메타(날짜·규격) |
| `caption` | 12/18 | 400 | 배지, 입력 도움말, 타임스탬프 |

- **숫자는 `font-variant-numeric: tabular-nums`** — 크레딧 잔액·가격·진행률·치수(px·mm)는 자릿수가 흔들리면 신뢰가 깨진다(Precise)
- 자간은 기본값. 한글 UI에서 자간 축소는 13px 이하에서 가독성을 해친다
- 최소 크기 12px. 그 아래로 내려가는 정보는 표시하지 않는 것이 맞다

## 3. 간격·형태

### 간격 — 4px 기반

`4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48 · 64`

- 카드 내부 패딩 20, 카드 사이 16, 섹션 사이 32~40, 화면 좌우 여백 24(데스크톱 콘텐츠 최대폭 1200)
- "넉넉한 여백"의 기준: **결과물 이미지 주변은 최소 24px** — 무대(surface)와 객석(bg) 사이에 숨 쉴 공간을 둔다

### 모서리

| 토큰 | 값 | 대상 |
|---|---|---|
| `r-sm` | 6px | 입력, 작은 버튼, 배지(사각형) |
| `r-md` | 8px | 버튼, 드롭다운 |
| `r-lg` | 12px | 카드, 시안·결과물 썸네일 |
| `r-xl` | 16px | 모달, 대표 포스터 영역 |
| `r-full` | 999px | 알약형 배지, 아바타 |

### 그림자 — 웜 틴트

순검정 그림자는 웜 뉴트럴 바탕에서 차갑게 뜬다. 그림자 색을 Charcoal 기반으로 통일한다.

| 토큰 | 값 | 대상 |
|---|---|---|
| `shadow-sm` | `0 1px 2px rgba(31,31,31,.05)` | 카드 기본 |
| `shadow-md` | `0 4px 12px rgba(31,31,31,.08)` | 카드 hover, 드롭다운 |
| `shadow-lg` | `0 12px 32px rgba(31,31,31,.14)` | 모달, **대표 포스터 영역** |

대표 포스터에만 `shadow-lg`를 주는 것은 의도다 — 무대 위 조명처럼, 화면에서 가장 떠 있는 것이 포스터여야 한다.

## 4. 컴포넌트

### 4-1. 버튼

| 종류 | 스타일 | 사용 |
|---|---|---|
| **Primary** | `#FF6A2A` 배경 + 흰 텍스트 16/600 | 화면당 1개 원칙. hover `#E95516`, pressed `#CC4A12` |
| **Secondary** | 흰 배경 + `--border` 1px + Charcoal 텍스트 | 이전·취소·보조 행동 |
| **Tertiary** | 배경 없음 + `--orange-text` 텍스트 | 인라인 행동("더 보기", "재시도") |
| **Destructive** | 흰 배경 + `--error` 1px 테두리·텍스트 | 삭제. filled 레드는 확인 모달의 최종 버튼에만 |
| **Disabled** | `#F3F0EC` 배경 + `--gray-disabled` 텍스트 | 커서 not-allowed. **비활성 사유를 툴팁·헬퍼로 반드시 표기** (예: ①의 "다음" — "필수 4항목을 채워주세요") |

크기: `lg` 44px(주요 CTA·모바일 기본) / `md` 36px / `sm` 30px(sm은 filled 오렌지 금지 — 대비 규칙). 로딩 중엔 레이블을 스피너로 교체하지 말고 **레이블 옆에 스피너** — 무엇을 누른 건지 사라지면 안 된다.

### 4-2. 입력

- 높이 40px, `r-sm`, 흰 표면 + `--border`. focus 시 `--focus-ring`
- 라벨은 위(13/600), 도움말·오류는 아래(12). 오류 시 테두리 `--error` + 메시지
- **미정 패턴**(①의 날짜·장소): 입력 오른쪽에 "미정" 체크. 체크 시 입력이 비활성 스타일로 바뀌고 값 자리에 `--neutral-badge` 알약 배지 "일정 미정" 표시. 미정은 오류가 아니므로 **레드·앰버를 쓰지 않는다**
- ②의 자동저장: 입력 그룹 우상단에 12px 캡션 "저장됨 · 방금" — 성공 토스트를 매번 띄우지 않는다

### 4-3. 카드

**프로젝트 카드 (0-B)** — 썸네일(대표 포스터, 3:4 비율 고정) + 공연명(h3) + 날짜·장르(body-sm, Warm Gray) + ⋮ 메뉴. hover 시 `shadow-md`. 배지는 썸네일 좌상단이 아니라 **텍스트 영역**에 — 포스터를 가리지 않는다.

**시안 카드 (③)** — 이미지가 카드의 전부다. 텍스트 없음. 선택 시 2px `#FF6A2A` 링 + 우상단 체크 원. 비선택 카드는 테두리 없이 `shadow-sm`만.

**결과물 카드 (⑥·⑦ 그리드)** — 미리보기 + 규격 라벨(body-sm) + 치수(caption, tabular) + 상태 배지. 다운로드 만료 시 미리보기는 그대로 두고 하단에 `--neutral-badge` "다운로드 만료 · 재생성 가능".

### 4-4. 배지

알약형(`r-full`), 12/600, 좌우 패딩 8px.

| 배지 | 스타일 |
|---|---|
| 정보 변경됨 | `--orange-soft` 배경 + `--orange-text` 텍스트 (행동 유도 — "최신 반영"으로 연결) |
| 원본 변경됨 | `--orange-text` 배경 + 흰 텍스트 (더 강한 단계 — 재구성 필요) |
| 미정 | `#F3F0EC` + Warm Gray |
| 처리 중 | `--orange-soft` + `--orange-text` + 12px 스피너 |
| 실패 | `#FCEBEB` + `--error` |
| 완료·저장됨 | `#E8F5EE` + `--success` |
| 다운로드 만료·보관 | `#F3F0EC` + Warm Gray |

"정보 변경됨"과 "원본 변경됨"을 같은 오렌지 계열의 **강도 차이**(soft/filled)로 구분하는 것은 Stage 4의 "배지 구분 표시" 요구를 색 체계로 옮긴 것이다.

### 4-5. 진행 표시

생성 작업(③ 시안, ⑥ 일괄변환)이 이 서비스의 핵심 대기 지점이다.

- 프로그레스 바: `--orange-soft` 트랙 + `#FF6A2A` 채움, 높이 6px, `r-full`
- 일괄변환: 규격별 행에 개별 상태(대기 `--gray` / 진행 스피너 / 완료 체크 `--success` / 실패 `--error` + "재시도" tertiary 버튼) — 부분 실패 UX(Stage 11)와 직결
- 대기 중 문구는 구체적으로: "시안을 만들고 있어요 · 보통 20~40초" — 막연한 스피너는 Energetic이 아니라 불안이다
- 스켈레톤: `#F3F0EC` 바탕에 shimmer. 시안 대기 중에는 3:4 비율의 스켈레톤 3장 — 결과물이 올 자리를 미리 보여준다

### 4-6. 모달·토스트

- 크레딧 확인 모달(생성 전 예상 소비량): 소비량 숫자는 h2·tabular, 잔액은 body-sm. 확인 버튼이 그 화면의 Primary가 된다
- 파괴적 행동 모달(삭제·탈퇴): 제목에 대상 명시("'겨울 나그네' 프로젝트를 삭제할까요?"), 30일 복구 안내 포함, 최종 버튼만 filled `--error`
- 토스트: 하단 중앙, 4초, Charcoal 배경 + 흰 텍스트. 실패 토스트에는 "재시도" 액션 포함. **성공 토스트는 아껴 쓴다** — 자동저장처럼 반복되는 성공은 인라인 캡션으로

### 4-7. 빈 상태

0-B 첫 방문: 일러스트 대신 **비어 있는 포스터 프레임**(3:4, `--border` 점선) + "첫 공연을 등록해보세요" + Primary CTA. 콘텐츠가 주인공이라는 원칙은 빈 상태에서도 — 앞으로 채워질 자리를 보여준다.

## 5. 화면별 적용 (③·⑦ 중심)

| 화면 | 무대 연출 |
|---|---|
| 0-A 소개 | 유일하게 오렌지를 넓게 써도 되는 곳(히어로 배경 `--orange-soft` 허용). 실제 생성 결과물 예시가 히어로의 주인공 |
| 0-B 홈 | 바탕 `--bg`, 카드 그리드. 화면의 채도색은 "새 프로젝트" CTA 하나 |
| ①·② 입력 | 폼은 흰 표면 카드 위에. 진행 단계 표시(①→④)는 상단에 가늘게, 현재 단계만 오렌지 |
| ③ 시안 선택 | **시안 3장이 화면의 70% 이상.** UI 크롬은 상단 얇은 바와 하단 액션 바뿐. 4개 액션 중 "확정"만 Primary, 나머지(재생성·다른 방향·더 보기)는 Secondary·Tertiary |
| ⑦ 대시보드 | 대표 포스터가 좌측(데스크톱) 또는 최상단(모바일)에 `shadow-lg`로. 결과물 그리드는 그 옆·아래. 페이지 배경에 포스터 팔레트를 흐리게 깔지 않는다 — 무대는 뉴트럴이어야 포스터가 산다 |
| ⑥ 일괄변환 | 규격 탭 + 3안 카드. 선택 링 규칙은 ③과 동일 |
| ⑧ 인쇄 | 업무도구 얼굴이 가장 필요한 화면 — 치수·수량·금액 전부 tabular, 경고는 앰버(차단 아님, Stage 4) |

## 6. 구현 — CSS 변수 (소스 오브 트루스)

```css
:root {
  /* 기본 팔레트 */
  --orange: #FF6A2A;        --orange-deep: #E95516;
  --orange-soft: #FFF0E8;   --charcoal: #1F1F1F;
  --gray-warm: #6B6865;     --border: #E7E3DF;
  --bg: #FAF8F5;            --surface: #FFFFFF;

  /* 파생 */
  --orange-pressed: #CC4A12; --orange-text: #BC3E0C;
  --gray-disabled: #A8A49F;  --bg-hover: #F3F0EC;

  /* 시맨틱 */
  --success: #1B7F4B; --success-bg: #E8F5EE;
  --warning: #7A5B00; --warning-bg: #FFF6DE;
  --error:   #C93030; --error-bg:   #FCEBEB;

  /* 형태 */
  --r-sm: 6px; --r-md: 8px; --r-lg: 12px; --r-xl: 16px;
  --shadow-sm: 0 1px 2px rgba(31,31,31,.05);
  --shadow-md: 0 4px 12px rgba(31,31,31,.08);
  --shadow-lg: 0 12px 32px rgba(31,31,31,.14);

  /* 모션 */
  --t-fast: 120ms ease-out;  /* hover·pressed */
  --t-base: 200ms ease-out;  /* 패널·모달 */
}
```

- React 컴포넌트는 이 변수만 참조한다. hex를 컴포넌트 코드에 직접 쓰지 않는다 — 색 하나를 바꿀 일이 생기면 여기 한 곳만 바꾼다
- 모션은 120/200ms 두 단계만. `prefers-reduced-motion` 존중
- **MVP는 라이트 단일 테마다.** 다크 모드는 범위 밖이되, 변수 구조를 지키면 나중에 `[data-theme]` 블록 추가로 확장된다
