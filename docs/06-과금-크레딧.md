# 과금·크레딧 설계 (Stage 6)

> **개정 이력**: 초판은 사업계획서의 "기간형 이용권 + 기본 크레딧" 구조를 따랐으나, **크레딧 단일 체계**로 개정하였다. 사업계획서(IR·지원서)에도 같은 변경을 반영해야 한다 — 아래 "사업계획서와의 차이" 참조.

## 수익 구조

```
가입 시 초기 크레딧 지급  →  소진하면 충전  →  사용량만큼 소비
+ 인쇄 주문 연계 (Phase 6)
+ B2B / Enterprise 계약
```

기간제 이용권을 두지 않는다. 기간이 아니라 **실제 사용량**에 과금하므로 다음이 자연스러워진다.

- 공연자는 매달 공연을 만들지 않는다. 쓰지 않는 달에 요금이 나가지 않는다
- 원가(이미지 생성 API 호출)와 매출이 직접 연동된다. 헤비 유저가 손실을 내지 않는다
- 프로젝트 만료·재활성화 같은 상태 관리가 사라진다. 프로젝트는 언제나 열려 있고 **생성 행위에만** 크레딧이 든다

## 1. 초기 지급

가입 시 일정량의 크레딧을 지급한다. 결제 없이 **공연 하나의 핵심 흐름(정보입력 → 시안생성 → 규격 몇 종 변환 → 다운로드)을 끝까지 경험**할 수 있는 양이어야 한다. 중간에 막히면 제품의 가치를 보기 전에 이탈한다.

**현재 지급량: 50크레딧** (`actset.credit.signup-grant`, MVP 임시값). 크레딧 단가가 정식으로 확정되기 전까지의 자리표시자이며, 아래 "확인이 필요한 사항"의 역산이 끝나면 교체한다.

정확한 지급량은 아래 크레딧 단가가 확정된 뒤 "포스터 1건 + 규격 3~4종"을 기준으로 역산한다.

## 2. 크레딧 소비 기준

원가에 비례해 액션마다 다르게 소비한다. **아래 절대값은 모두 MVP 임시 크레딧이다** — 원가 기준선이 잡히기 전까지의 자리표시자이며, 실제 크레딧 단가가 확정되면 교체한다.

### MVP 구현 범위 (Phase 1·2)

| 액션 | 화면 | 크레딧 | 근거 | 구현 |
|---|---|---|---|---|
| 포스터 최초 생성 (3장 세트) | ③ | **10C / 세트** (`mode=initial`) | 이미지 생성 API 신규 호출. 장수와 무관한 정액 | `CostEstimateService` |
| 포스터 재생성 · 다른 방향 보기 · 이 방향으로 더 보기 (3장 세트) | ③ | **5C / 세트** (`mode≠initial`) | 최초 생성보다 낮은 단가로 재시도 부담을 줄인다 | `CostEstimateService` |
| 규격 변환 1종 | ⑥ | **2C** (`mode=initial`) | Recomposition 중심, 저장된 레이어 재배치. 규격당 정액(변형 수와 무관) | `CostEstimateService` |
| 규격 재생성 1종 | ⑥ | **1C** (`mode=regenerate`) | 같은 규격을 다시 생성 — 최초 변환의 절반 | `CostEstimateService`(신규) |
| 포스터 다시 만들기 | ⑤·⑦ | 최초 생성과 동일(10C/세트) 예정 | 3-7(원본 재생성) 미구현 — 실제 레이어 재분해 필요 | 미구현 |
| 최신 반영 — 원본 변경분 | ⑦ | 규격 변환과 동일(2C × 대상 수) 예정 | 4-5 미구현 | 미구현 |
| 최신 반영 — 정보 변경분 | ⑦ | **무과금** | 텍스트·사진(PHOTO) 레이어만 재합성 — 생성 API 미호출 | 미구현(4-5) |
| 포스터 자동 반영 | (자동) | **무과금** | 사용자가 요청한 생성이 아니고, 비주얼 레이어를 재사용하므로 생성 API를 부르지 않는다 | 구현됨(4-4) |
| 최소 편집(위치·크기 조정) | ⑥ | **무과금** | 합성만 다시 한다 | 미구현(3-6) |
| 다운로드·인쇄 초안 | ⑦·⑧ | **무과금** | 이미 만든 것을 받는 행위다 | 구현됨 |

무과금 항목을 명시한 이유는, **이미 만든 결과물을 쓰는 데 추가 비용이 들면 고객이 제품을 신뢰하지 못하기 때문**이다. 크레딧은 "새로 만드는 것"에만 든다.

`규격 재생성`은 최초 변환과 별개 액션이다 — ⑥ 화면에서 이미 생성된 규격을 다시 뽑을 때 `POST /projects/{id}/recompose`를 `mode: "regenerate"`로 호출하면, 같은 `format_codes` 1건 기준 1C가 차감된다(Stage 11).

docs/01이 MVP 범위 밖으로 명시한 기능들이다. 코드에 걸 곳이 아직 없어(도메인·서비스·엔드포인트 전부 미착수) 크레딧 로직에는 반영되지 않았고, 실제 기능 착수 시 이 표의 값을 `CostEstimateService`에 상수로 옮긴다.

### 원가 기준선 — Ideogram 4.0 단가 확인분

이미지 생성 벤더를 Ideogram 4.0으로 잡으면 장당 단가가 확정된다(Default $0.06 / Quality $0.10, Stage 9).

| 액션 | 이미지 생성 호출 | 원가(Default 기준) |
|---|---|---|
| 시안 3안 생성 | 3장 | $0.18 ≈ **250원** |
| 재생성 / 다른 방향 보기 | 3장 | $0.18 ≈ **250원** |
| 포스터 다시 만들기 | 3장 + **레이어 재분해 1회** | $0.18 + 분해비 ≈ **250원 + α** |
| 규격 변환 1종 | 배경 재사용 시 0장 (아웃페인팅 필요 시 1장) | 0원 ~ 약 85원 |
| 최신 반영(정보 변경분) | 0장 | **0원** |
| 포스터 자동 반영 | 0장 | **0원** |

여기에 스토리지·전송·서버 비용이 더해지지만, 지배적인 변동원가는 이미지 생성 호출이다.

**레이어 분해 비용은 아직 비어 있다.** ④ 확정과 포스터 재생성 시 Qwen-Image-Layered를 1회 호출하는데, 서버리스 GPU 실행 시간에 따라 결정되므로 PoC Q6에서 실측한 뒤 위 표의 α를 채운다.

**규격 변환의 원가가 예상보다 낮다**는 점이 중요하다. 저장된 레이어를 재배치하면 생성 API를 부르지 않으므로, 일괄변환은 시안 생성보다 훨씬 싸다. 다만 가로 규격의 아웃페인팅이 필요해지면(PoC Q4) 이 계산이 바뀌므로, **최종 크레딧 단가는 아웃페인팅 방식이 확정된 뒤 산정한다.**

**티어 분리 전략**을 쓰면 원가가 더 줄어든다. 후보는 Default($0.06)로 뽑고 사용자가 고른 안만 Quality($0.10)로 다시 생성하면, 버려질 후보에 비싼 단가를 쓰지 않는다. 이 방식 채택 여부는 두 티어의 결과 차이를 PoC에서 확인한 뒤 정한다.

충전 단가는 위 원가에 마진·고정비를 얹어 산정하되, 마진율은 고객 인터뷰에서 확인한 지불 의사와 함께 정한다.

## 3. 차감·환불 규칙

- **차감 시점은 작업 등록 시**다. 생성 후 차감하면 무료로 만들 여지가 생기고, 확인만 하고 미루면 동시 요청에서 잔액이 음수가 된다
- 잔액 갱신·이력 기록·작업 등록을 한 트랜잭션으로 묶고, `credit_balance`에 `CHECK (>= 0)`을 걸어 DB가 마지막 방어선이 되게 한다
- **작업이 실패하면 환불**한다. 일괄변환의 부분 실패는 실패한 규격 몫만 되돌린다
- 잔액 부족 시 작업을 등록하지 않고 `402`로 안내한다. 생성 전에 예상 소비량을 보여준다(Stage 11 `GET /credits/estimate`)

크레딧에 **유효기간을 두지 않는다.** 충전한 크레딧이 소멸하면 고객의 자산을 빼앗는 것으로 받아들여지고, 재구매를 막는다.

## 4. 충전

소량·중간·대량 구간을 두고 대량일수록 단가를 낮춘다. 반복 사용 고객에게는 상위 플랜(대량 크레딧 + 고급 기능 우선 이용)을 제공한다.

베타 기간에는 결제를 붙이지 않고 **관리자 지급**만 사용한다(Stage 11).

## 5. 프로젝트 보관과 대용량 파일

프로젝트는 고객의 공연 자산이므로 **기한 없이 보관**한다. 공연정보·설정·선택기록·미리보기 이미지는 영구 보관 대상이다.

대용량 원본 파일만 다르게 다룬다.

| 구분 | 보관 |
|---|---|
| 공연정보·프로젝트 설정·레이아웃 데이터·선택 기록 | 영구 |
| **미리보기 이미지**(장변 800px 내외) | **영구** |
| 대용량 원본 파일(임계값 이상) | **생성일 + 90일** |

90일이 지나면 원본 파일만 삭제하고 레코드와 미리보기는 남긴다. 따라서 **다운로드는 못 해도 어떤 이미지였는지는 계속 볼 수 있다.** 프로젝트 목록에서 결과물이 통째로 사라지지 않는다.

다시 받고 싶으면 재생성하면 되고, 이때 크레딧이 소비된다. 저장 공간을 상품으로 팔지 않고, 평균 저장비를 크레딧 단가에 포함시킨다.

기준일을 이용권 만료가 아니라 **생성일**로 잡은 것은 기간제를 없앴기 때문이다. 계정에 만료일이라는 개념 자체가 없다.

### 대용량 임계값 — 재산정 필요

앞서 500MB로 정했으나, 실제 산출물 크기를 계산해 보면 **이 기준으로는 정책이 한 번도 발동하지 않는다.**

| 결과물 | 픽셀 | 예상 용량 |
|---|---|---|
| SNS·웹용 JPEG | ~1~2M | 0.3~1MB |
| A3 포스터 300dpi JPEG | 17.4M | 5~15MB |
| A3 포스터 300dpi PNG | 17.4M | 40~80MB |
| 현수막 5m 150dpi JPEG | 122M | 50~120MB |

가장 큰 현수막 인쇄 원본도 500MB에 미치지 못한다. 정책의 목적(인쇄용 고해상도 원본의 저장비 통제)을 살리려면 임계값을 낮춰야 하며, **50MB를 제안한다.** 이 값이면 인쇄용 원본 대부분이 대상이 되고 화면용 결과물은 영구 보관된다.

임계값은 코드 상수가 아니라 **설정값**으로 두어 운영 중 조정할 수 있게 한다. 최종 확정은 실제 산출물 크기 분포를 관측한 뒤에 한다.

## 6. 사업계획서와의 차이 (수정 필요)

현재 사업계획서는 다음과 같이 서술되어 있어 이 문서와 어긋난다. IR·지원서 갱신 시 함께 고쳐야 한다.

| 사업계획서 서술 | 변경 후 |
|---|---|
| "기간형 이용권 + 기본 크레딧 + 추가 크레딧 + 상위 요금제" | **초기 지급 크레딧 + 충전 크레딧 + 상위 플랜** |
| "Project Pass 90 — 90일 이용권" | 기간제 폐지 |
| "프로젝트당 500MB까지 장기보관, 이용권 종료 후 90일" | **대용량 원본은 생성일 + 90일**, 미리보기는 영구 |
| 핵심 지표 "이용권 재구매율" | **크레딧 재충전율** |

수익 구조 네 축 중 ①만 바뀌고 ②크레딧 ③인쇄 ④B2B는 그대로다. 다만 지표 정의가 바뀌므로 **"두 번째 공연에서도 다시 구매하는가"**라는 장기 성장 판단 기준은 "이용권 재구매"가 아니라 "두 번째 프로젝트 생성 + 크레딧 재충전"으로 다시 정의해야 한다.

## 7. 베타 운영

베타는 크레딧 결제를 붙이지 않는다. 다만 **크레딧 차감 로직 자체는 처음부터 구현한다.** 나중에 붙이면 소비량 데이터가 없어 단가를 정할 근거가 생기지 않는다.

- 베타 계정에는 넉넉한 크레딧을 관리자 지급한다
- 소비는 정상적으로 기록해 **액션별 실제 소비 분포를 관측**한다
- 이 데이터가 정식 출시 시 지급량·충전 단가의 근거가 된다

## 확인이 필요한 사항

1. 가입 초기 지급량 — 현재 코드상 임시값은 **50크레딧**. 위 §2 임시 단가로 "포스터 1건(최초 생성 세트 10C) + 규격 3종(2C×3=6C)"을 계산하면 16C로, 여러 번 반복해도 될 만큼 여유가 있다. 크레딧 단가 확정 후 다시 역산해 교체해야 한다. 위 원가표로는 대략 **300~400원어치**가 이 흐름 한 번에 해당한다
2. 크레딧 절대 단가 — 아웃페인팅 필요 여부(PoC Q4)와 레이어 분해 비용(PoC Q6)이 정해져야 확정된다
3. **대용량 임계값 50MB 확정 여부** — 위 재산정 근거 참고
4. 충전 구간과 상위 플랜 가격 — 고객 인터뷰(목표 20건) 후 확정
5. 크레딧 **현금 환불 정책** — 유효기간이 없어 미사용 잔액이 부채로 누적된다. 환불 기준·수수료·서비스 종료 시 처리를 유료 출시 전에 정해야 한다(Stage 15)
6. 사업계획서 개정 반영 시점
